# 🎬 Tiers — общий тирлист фильмов и сериалов

> **Живой сайт:** https://16angeles.github.io/tierlist/
> **Данные (приватные):** https://github.com/16Angeles/tierlist-data
> **Ссылка для друга:** открывает сайт с уже подставленными настройками — останется вставить свой токен:
> `https://16angeles.github.io/tierlist/?backend=github&gh=16Angeles/tierlist-data&branch=main&path=tierlist.json&list=our-list`

Красивый тирлист по **10-балльной шкале**, который работает на статике (GitHub Pages) и
синхронизируется между двумя компьютерами. Никакого сервера не нужно — данные лежат
в JSON-файле вашего GitHub-репозитория.

```
S  9–10    Шедевр
A  7–8.9   Отлично
B  5–6.9   Хорошо
C  3–4.9   Средне
D  1–2.9   Слабо
```

Оценки можно ставить **с шагом 0.1** — например, 8.5 «Игре престолов».
Кликните по бейджу с оценкой на постере: откроется пикер с ползунком,
крупным числом (можно вписать любое значение вручную), кнопками ±0.5
и быстрым выбором целых 1–10.

### Оценка по 5 факторам

Кроме одной оценки у каждого фильма есть развёрнутая шкала из пяти ползунков:

| Фактор | Что оцениваем |
|---|---|
| Сюжет | история и её развитие |
| Развлекательность | насколько затягивает |
| Музыкальное сопровождение | саундтрек и звук |
| Атмосфера | мир, настроение, картинка |
| Пересмотрибельность | хочется ли пересмотреть |

Итоговая оценка в тирлисте **считается сама** — это взвешенное среднее по пяти
ползункам (по умолчанию веса равные, их можно менять в
**Настройки → Факторы**). Тянуть ползунки можно и при создании карточки,
и позже — в пикере на вкладке «По факторам».

Ползунки есть и у каждого участника свои: в раздельном режиме вы ставите свои
пять оценок, друг — свои, а тир определяется по средней.

## Что умеет

- 🎯 **Drag & drop** — перетащите постер в тир, оценка проставится автоматически.
- 🔢 **10-балльная шкала** — дробные оценки с шагом 0.1 (8.5, 7.3), пикер с ползунком.
- 🎛️ **5 факторов** — сюжет, развлекательность, музыка, атмосфера, пересмотрибельность:
  5 ползунков, итоговая оценка и тир считаются автоматически.
- 👥 **Два режима оценок**
  - *Общая* — одна оценка на фильм, решаете вместе;
  - *Раздельная* — у каждого своя оценка, тир определяется по **среднему**.
  - В раздельном режиме на каждом устройстве выбирается, **кто вы** (Настройки → Участники),
    выбор запоминается в браузере — так каждый ставит свою оценку.
- 🔄 **Синхронизация** — изменения у друга появляются у вас за несколько секунд.
- 🎨 **Постеры** — встроенный поиск по TMDB (постеры, год, тип) или свои ссылки.
- 📊 **Статистика** — средняя оценка, распределение по тирам, топ и антитоп.
- 🖼️ **Экспорт в PNG** — красивая картинка тирлиста, чтобы кинуть в чат.
- 🔍 Поиск, ⌨️ горячая клавиша `N` для добавления, 📱 адаптив под телефон.
- 💾 Импорт/экспорт JSON, 🌙 тёмная тема, ⬇️ полностью офлайн-совместимый фронтенд.

## Быстрый старт (свой сайт)

### 1. Задеплойте на GitHub Pages

```bash
git init
git add .
git commit -m "tierlist"
git branch -M main
git remote add origin https://github.com/<ваш-ник>/tierlist.git
git push -u origin main
```

Затем в репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
Через минуту сайт появится на `https://<ваш-ник>.github.io/tierlist/`.

> GitHub Pages на бесплатном плане работает только для **публичных** репозиториев —
> поэтому код лежит в публичном `tierlist`, а данные — в приватном `tierlist-data`.

### 2. Запустите локально (по желанию)

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
```

## 🤝 Как работать вдвоём с разных компьютеров

Самый простой способ — **GitHub как база данных**: тирлист лежит файлом `tierlist.json`
в репозитории, приложение читает и пишет его через GitHub API.

### Схема репозиториев

| Репозиторий | Видимость | Что внутри |
|---|---|---|
| `tierlist` | публичный | код приложения + workflow для Pages (сайт) |
| `tierlist-data` | **приватный** | `tierlist.json` — ваши оценки (сюда пишет приложение) |

Открытый код — плюс, ваши оценки при этом никому не видны.

### Настройка (один раз)

1. Откройте сайт → ⚙️ **Настройки → Подключение**:
   - Backend: **GitHub**
   - Владелец: `<ваш-ник>`
   - Репозиторий: `tierlist-data`
   - Ветка: `main`
   - Файл: `tierlist.json`
   - Token: ваш токен
   - **ID списка**: одинаковый у обоих (например `our-list`)
2. Нажмите **Проверить подключение** → «Подключение работает».
3. Вкладка **Данные** → **Скопировать ссылку** → отправьте другу.

### Что делает друг

1. Открывает присланную ссылку — репозиторий, ветка, файл и ID списка подставляются сами.
2. Вставляет **свой токен** (Настройки → Подключение → Token) и жмёт «Сохранить».
3. Готово: тирлист общий, изменения подхватываются за несколько секунд.

### Токены

Токен — это Personal Access Token, которому нужны права на запись в репозиторий данных:

| Тип токена | Как создать | Права |
|---|---|---|
| **Классический** | Settings → Developer settings → Personal access tokens → *Tokens (classic)* | галочки `repo`, `workflow` |
| **Fine-grained** | Settings → Developer settings → Personal access tokens → *Fine-grained* | Repository access: только `tierlist-data`; Permissions: `Contents: Read and write` |

> 💡 Данные читаются и пишутся напрямую из браузера — сервер не нужен.
> Токен хранится только в `localStorage` вашего браузера и никуда не отправляется.
> Держите репозиторий данных приватным и не используйте один токен для разных сайтов.
> Если токен утёк — перевыпустите его в настройках GitHub.

### Что происходит при конфликтах

Слияние построчное: у каждой оценки и у каждого порядка своя метка времени,
поэтому если вы одновременно с другом поставили разные оценки — победит более поздняя,
а всё остальное (названия, порядок, оценки второго участника) сохранится.

## ⚡ Альтернатива: Supabase (обновления в реальном времени)

Если хотите мгновенную синхронизацию вместо опроса раз в 5 секунд:

1. Создайте проект на [supabase.com](https://supabase.com), выполните SQL:

```sql
create table tierlist_docs (
  id         text primary key,
  doc        jsonb not null,
  updated_at timestamptz default now()
);

alter table tierlist_docs enable row level security;

create policy "read"   on tierlist_docs for select using (true);
create policy "write"  on tierlist_docs for insert, update
  using (true) with check (true);
```

2. В Supabase → Table Editor → включите **Realtime** для таблицы `tierlist_docs`.
3. В приложении: **Настройки → Подключение → Supabase**, вставьте Project URL и
   `anon` public key, укажите одинаковый ID списка.

## ⚙️ Структура проекта

```
src/
  App.tsx                 — оболочка: фон, drag-and-drop, модалки
  types.ts                — модель данных (Doc, Item, Rating)
  lib/
    tiers.ts              — шкала 1–10, тиры, средние, расчёт целевой оценки
    factors.ts            — 5 факторов, веса, расчёт итоговой оценки

    sync/
      github.ts           — GitHub Contents API + ETag-поллинг
      supabase.ts         — Supabase Realtime (ленивый импорт)
      local.ts            — localStorage
  components/             — TopBar, TierBoard, TierRow, PosterCard, модалки
  state/
    useTierDoc.ts         — состояние, автосохранение, синхронизация
    useTierDnd.ts         — логика перетаскивания между тирами
```

  и в репозиторий не попадают.
- GitHub-токен виден в devtools, поэтому держите репозиторий приватным и не
  используйте один токен для разных сайтов.
- Если токен утёк — просто перевыпустите его в настройках GitHub.
